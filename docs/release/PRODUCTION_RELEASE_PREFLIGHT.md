# Production release preflight

`node scripts/production-release-preflight.mjs <candidate-config> <metadata-names-only.json> <release-evidence.json>` is a read-only guard. It does not call Cloudflare or deploy. It reads candidate migration filenames from the configured `migrations_dir` and prints `GO` only when the candidate matches the recorded production target, sanitized metadata matches the Worker, the migration ledger is complete with no pending candidate migrations, every release gate has affirmative evidence, and owner deployment approval is recorded.

The metadata input must contain only the worker name, active version ID and traffic percentage, route, compatibility date and flags, `workersDev`, `previewUrls`, and `keepVars` settings, D1 name and ID, D1 migration ledger names, secret binding **names**, plain-text variable **names**, and rate-limit binding **names**. The migration ledger object is `{ verified: true, source: "wrangler d1 migrations list", applied: string[], pending: string[] }`; it must account for every candidate migration in order. Do not include binding values, account data, tokens, ciphertext, or keys. Secret values are neither needed nor read. Extra metadata fields fail the preflight.

The evidence input must set these booleans only after the named checks are actually complete: `productionEncryptionCompatibility`, `productionSourceBehaviorCompatibility`, `syntheticD1MigrationAndTimeTravelRestore`, `protectedProductionBackupRestore`, `coordinatedRollback`, `productionOAuthAndMcpAcceptance`, `billingAuthorization`, `checksAndSecurity`, and `ownerDeploymentApproval`. It must also include `d1MigrationRehearsal` with the exact candidate migration sequence, a successful Time Travel restore to a named checkpoint, successful reapplication of the migrations after that checkpoint, data-preservation checks, and `syntheticOnly: true`. `rollbackPrerequisites` must identify the exact previously deployed Worker version and attest that it is retained, isolated rollback was tested, protected D1 restore and migration replay passed, and post-rollback smoke checks passed. Missing, false, malformed, or inconsistent evidence remains `NO-GO`.

The committed expectations currently describe Worker `classroom-desk` v22 and its observed D1, route, and runtime. The CLI reads only local SQL filenames; remote migration state must be collected separately with a read-only metadata command and supplied as names only. Update expectations only after new Cloudflare metadata is independently verified. The script is an additional guard, not proof of source parity or data compatibility.
